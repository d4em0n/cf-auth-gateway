# LibreChat v0.8.9 profile

Target: official v0.8.9, commit `d4e85d2205c78413ee27d631d7e3b7313556f21d`, upstream image digest `sha256:4a3967a47031c1fdba8302a6a341be7671101e40b617f7934ba25aac69fcea2b`. The owner's installed derivative adds workspace/file integrations. Testing uses that same image with an independent MongoDB database, uploads, account and generated JWT secrets. Production configuration/state is not copied or modified.

The profile is `profiles/librechat-v0.8.9.yaml`; the engine contains no LibreChat-specific code. Version/build changes require a profile audit and browser regression test. Some filenames, including the workbox bootstrap, are build-specific.

| Route or material                              | Verified contract                                                                                                                                                                              |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/user`                                | Session-JWT validator; requires bearer auth, returns HTTP 200 JSON with root `id`. Not `/api/auth/me`.                                                                                         |
| Access credential                              | `Authorization: Bearer <JWT>`; no access-token cookie. Default lifetime 15 minutes. QA accelerates it to 60 seconds.                                                                           |
| `POST /api/auth/login`                         | Local email/password login; returns token/user and three separate session cookies. Invalid password returns 404 in this version.                                                               |
| Refresh cookies                                | `refreshToken`, `token_provider` are HttpOnly, Secure and SameSite=Strict; readable `session_hint` is a hint, never gateway authentication. Host-only, Path=/; refresh defaults to seven days. |
| `POST /api/auth/refresh`                       | Cookie-based, rotates refresh token/hash and issues access token. No access bearer required. A missing refresh token can return 200 plain text; it must never be a credential validator.       |
| `POST /api/auth/logout`                        | Backend requires JWT, clears cookies and deletes refresh session. An existing JWT may remain valid until expiry; this is backend behavior.                                                     |
| Shell/assets                                   | Exact root/login/index, manifest, service-worker bootstraps, robots and theme bootstrap; known build directory `/assets/`. No generic extension bypass or `/images/` public prefix.            |
| `/c/` GET/HEAD                                 | SPA shell only. Reload starts from cookies before a bearer is available; private data still comes from protected APIs. Other SPA paths require explicit review.                                |
| `GET /api/config`                              | Explicit pre-login sanitized configuration; authenticated response can vary. No shared gateway caching.                                                                                        |
| `/api/convos`, `/api/files/*`, `/api/agents/*` | Protected; backend still authorizes the individual resource.                                                                                                                                   |
| Streaming                                      | Chat start POST, then authenticated `GET /api/agents/chat/stream/:streamId`; `resume=true` supports replay. Browser conversations use SSE, not WebSockets.                                     |

Source inspection: `api/server/routes/auth.js`, `routes/user.js`, `controllers/UserController.js`, `strategies/jwtStrategy.js`, `services/AuthService.js`, `routes/agents/index.js`, and `packages/api/src/auth` at the pinned commit. See [tagged upstream](https://github.com/LibreChat-AI/LibreChat/tree/d4e85d2205c78413ee27d631d7e3b7313556f21d) and [auth documentation](https://www.librechat.ai/docs/configuration/authentication); current docs may describe later versions.

The deployed owner configuration disables registration, social signup/login and password reset, and has no configured OIDC/Google provider or enabled passkey login. These callbacks are not public in this profile. Two-factor temporary/setup routes are explicitly listed with rate limiting so local-account MFA can progress; the optional challenge flow has a strict request contract. Required-enrollment setup has strict contracts verified through a separate enforced-MFA backend and local workerd; existing deployment authentication settings are unchanged. See the [request-contract scope](../request-contracts/librechat.md) and current results. Passkey, OIDC, SAML, password-reset and email-verification flows need separate explicit routes and real integration before enabling them. Do not expose `/api/auth/` or `/oauth/` wholesale.

Agent API keys are a different credential class. `/api/user` is not their validator. They are intentionally unsupported and fail first-use session-JWT validation; do not configure a refresh cookie or agent key as a session credential. Public shared links, query-token downloads and integration callbacks are also unsupported by this profile; sharing inside an authenticated account remains backend-controlled. No unauthenticated OPTIONS bypass is provided; this is a same-origin deployment, and native HTTP clients do not require CORS preflight.

LibreChat applies `ua-parser-js` to chat/file requests and can return an SSE `Illegal request` error to clients without a browser-compatible User-Agent. Native clients must follow the backend's contract; the gateway preserves the original User-Agent. Concurrent clients must serialize refresh and retain the winning rotated cookies; the gateway does not retry a refresh POST.
